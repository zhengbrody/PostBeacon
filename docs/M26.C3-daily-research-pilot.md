# C.3 — Explicitly delegated daily public research pilot

2026-10-25. Local implementation, not an enabled production service or a 24-hour SLA.

## The visible product

Today contains a daily delegation card above the existing CMO Brief. A founder
chooses an audience, useful trial task, feedback question, public product entry,
one to three public search queries, and one to five exact public hostnames.
Separate approvals cover Tavily search and necessary OpenAI draft processing.
Typing makes no provider request. Editing clears both approval checkboxes.

Explicit save returns an authorization revision and a 30-day expiry. Review,
Check now, and Pause expose actual server receipts; an unsaved editor is never
the standing authorization. Example mode is ephemeral and makes no API, model,
search, scheduler or account-storage calls. It labels every simulated action.

Results remain proposals. The existing task review, context validation, dual
confirmation, reducer-owned planned queue, Truth Gate and manual publish flow
remain authoritative. Search hits and matching quotes are not proof of demand,
community permission, a customer conversation or successful promotion.

## Architecture

`DailyResearchMission` → `useAgentMission` → typed `lib/api.ts` → authenticated
`/api/agent-missions` → `agentMissionServer` → transactional Supabase RPCs.
The separately authenticated `/api/agent-missions/tick` can reserve up to three
due missions per request and uses the existing request-backed Agent worker.
No new framework, dependency, model, connector or provider fallback was added.

The worker reserves search once, submits only approved queries/domain filters,
selects at most two eligible sources, and independently fetches their quotes.
Those source fetches reject redirects, use the existing DNS-pinned SSRF boundary,
and never invoke a paid browser renderer. No verified source means no model call.
At most one existing OpenAI model request follows verified source checks.

## Privacy, permissions and lifecycle

- Exact host permissions do not include subdomains. Restricted social platforms,
  credential-bearing/query/fragment links and obvious identity paths are excluded.
- Conservative checks reject obvious emails, handles, credentials and secrets.
  This is not complete personal-data detection; approved inputs must be public.
- Full profiles are not used to invent search queries. Only necessary verified
  product facts, the approved Brief, restrictions and filtered excerpts reach the
  existing draft model. Raw search metadata and whole pages are not persisted.
- Background processing is OpenAI-only. Prior one-off DeepSeek consent is never
  inherited as standing authorization, and no automatic fallback is allowed.
- Owner-only RLS reads and service-only writes/RPCs protect authorizations. Composite
  project/owner foreign keys prevent cross-account task and mission attachment.
- Each mission revision has at most one reservation per UTC day. Reauthorization
  creates a new revision; all revisions still share the existing 10/user/day and
  100/global/day Agent limits. A check can use up to three paid search requests and
  one model request; count limits are not a hard dollar-spend guarantee.
- Lease, revision, expiry and cancellation checks fence paid checkpoints and final
  writes. Each checkpoint atomically compares the server-validated project version;
  intervening autosaves reject the old search/model/completion request. Account
  deletion uses the same project-first lock order to avoid worker/delete deadlocks.
  Paid work whose checkpoint was already granted cannot be recalled or
  refunded by pausing. Ambiguous search/model attempts are not automatically retried.
- Authorization expires after 30 days without silent renewal. Background checks
  preserve project activity timestamps instead of defeating inactivity retention.
- Mission settings and task/search receipts are covered by account export and
  project/account deletion. Missing previously installed history fails closed;
  uninstalled legacy accounts remain exportable. Pause does not delete history.

## Scheduling boundary

There is deliberately no new cron entry in `vercel.json`. A trigger must be
separately configured and accepted after installation. Each trigger handles at
most three due authorizations; `last_dispatch_at` rotates stale entries fairly.
This is a small pilot, not a scalable dispatcher or guaranteed daily delivery for
an arbitrary number of users. Before expanding, add queue/durable execution,
capacity-aware scheduling, operational alerts and a separately approved spend cap.
There are no unsolicited emails, auto-posts, social OAuth connections, DMs, contact
harvesting or automatic community replies.

## Installation and acceptance order

Do not execute SQL or change production flags as a side effect of build/deploy.

1. Review and separately approve the additive installation. Preserve the base
   schema; install `supabase/migrations/20261025_agent_runs.sql`, then
   `supabase/migrations/20261026_agent_missions.sql`.
2. Run `supabase/audit-agent-runs.sql` (eight PASS) and
   `supabase/audit-agent-missions.sql` (ten PASS). SQL success alone is not an audit.
3. Separately approve paid public test data and verify two real account boundaries,
   export/deletion coverage, one actual source/model run, pause, expiry and no-fit.
4. Only then enable server-only `AGENT_RUNS_ENABLED` and `AGENT_MISSIONS_ENABLED`
   with configured service storage, `SEARCH_API_KEY` and `OPENAI_API_KEY`.
5. Separately register the authenticated tick using `CRON_SECRET`; verify actual
   task receipts and capacity before claiming unattended operation.

The last production investigation found the original Agent installation absent.
This round has not changed production SQL, flags, scheduler configuration, social
accounts or paid-provider state. Local tests are not authenticated production QA.

## Verification

The isolated `npm run test:agent-db` harness installs both migrations and audits,
uses disposable fictional users, and checks concurrency, owner isolation, shared
budgets, leases, revocation, expiry, migration reruns and cleanup. It accepts no
production URL, reads no environment file and never touches production data.
Offline API/worker tests use mocked search/model/storage seams. Browser acceptance
uses the built application with explicitly fictional data at desktop and mobile
sizes. Final gate results are recorded in AGENTS.md after revalidation.

Local acceptance: **801 offline tests pass**, three gated live tests skipped;
typecheck, lint, format, dependency audit (zero known advisories) and optimized
build pass on Node 24.22.1. Both database audits and **32 isolated PostgreSQL
scenarios** pass, including paid-checkpoint/autosave races and concurrent deletion.
Six existing public smoke probes plus four mission auth/origin/operator probes
pass against localhost. Built-app fictional browser QA passes at actual CSS
1280×720 and 375×812 without horizontal page overflow or captured warnings/errors:
query/domain edit, separate consent, authorization receipt, check preview, pause,
and the existing trial review → dual confirmation → actual Today queue selection.
Screenshots are local artifacts under `artifacts/daily-agent-20261025/`, not product
attachments or real-provider evidence. No authenticated cloud mission or paid
provider acceptance was performed.
