# C.2.2 — Brief to a reviewable product trial

2026-10-25. An early, visible CMO interaction slice, not autonomous distribution.

## What changed

Today opens with a three-question Brief: audience, one useful product task, and one
feedback question. The existing Success Contract remains authoritative. Optional
delivery settings expose the real entry URL, channel/venue, proposed three steps,
and evidence mode. Editing a Brief does not call a provider or save a task.

The product-led mode needs verified product facts, not external demand excerpts.
It prepares one proposed invitation and explicitly says that no customer demand or
venue permission was verified. Evidence-led mode preserves the old one-to-three
explicit-source workflow; missing mode in old data means evidence-led, never an
automatic product-led fallback. Failed source checks do not trigger another mode.

The reviewable kit contains a draft, cited fact IDs, entry, proposed trial steps,
feedback question, success rule and screenshot instructions. These are instructions
for the founder, not generated screenshots or proof that the product was used.
Two explicit confirmations are still required before the reducer appends a draft
and planned experiment. The actual queue receipt drives the move into Today.

## Architecture and safety

- No new framework, dependency, model, connector or scheduler. The existing bounded
  server worker still reserves at most one model attempt per task, with no retry or
  fallback. Product-led tasks fetch no external demand pages.
- `trialBrief.ts` supplies editable workflow suggestions, not invented feature facts.
  `CmoBrief` is presentational; the workbench owns only ephemeral inputs and review.
- Existing `opportunityResearch` normalizers own the mode boundary. Product-led
  snapshots require valid fact IDs and an exact reviewed-context key (at most 50k
  characters), and cannot contain a demand source.
- The reducer owns queue and publish mutations. New trial snapshots preserve their
  reviewed context. Changes to product facts (even with the same ID), profile,
  Success Contract, URL or banned claims require a fresh review before publication.
  Published history is preserved rather than rewritten against current facts.
- `trialDraftSafety.ts` checks the actual platform and post index. Today, individual
  library cards and bulk-copy use the same trial entry/context/banned-claim rules.
  Derived Share Kit copies are disabled for trial drafts; the approved invitation
  remains the manual publishing path. Ordinary Truth Gate checks still apply.
- Storage version 12 restores old source-backed records without manufacturing
  provenance. Markdown/JSON export keeps historical records even when current
  publishing is blocked. No new SQL is required for these JSON shape additions.

## What is deliberately not enabled

Real persistent tasks still require the separately approved Agent SQL installation,
eight-row audit, server-only feature flag and real-account/provider acceptance.
This release does not authorize any of those writes, paid calls or real posting.
The editable fictional walkthrough makes no model calls and never saves account
data. Manual Copy/Open is not proof of a platform publication.
