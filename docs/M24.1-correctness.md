# M24.1 — Correct experiment history

## Problem

The workspace originally stored one mutable `Experiment.verdict`. Recording a
72h result replaced the 24h read, while Timeline rendered that final value next
to every Outcome. The same platform-level task id also treated a channel as
permanently complete after its first publish. Finally, historical `trackedUrl`
values were rendered directly as links.

These are correctness defects, not presentation defects: future learning,
memory and repeat-use features cannot trust history until they are fixed.

## Data contract

- Every new `Outcome` owns its contemporaneous, deterministic `verdict`.
- `Experiment.verdict` remains only a materialized latest/final summary so old
  consumers and saved projects continue to work.
- A legacy experiment-level verdict is never copied into an Outcome. Timeline
  and Markdown export label it **Historical final verdict — checkpoint
  unavailable**.
- Scheduled 24h/72h Outcome verdicts close learning loops. Manual early reads
  remain useful but do not inflate retention.
- The normalized `outcomes.verdict jsonb` mirror persists the same object. The
  migration intentionally performs no historical backfill.

## Identity contract

- Draft execution key: `<platformId>-<postIdx>`.
- Publish task: `post:<platformId>:<postIdx>`.
- Checkpoint task: `record:<experimentId>:<24h|72h>`.
- Experiment execution: random UUID.
- Legacy `post:<platformId>` task ids map only to draft index 0; they cannot
  suppress later variants on that channel.

This fixes same-channel second rounds without introducing M29's future Planned
Experiment Queue early.

## URL contract

`normalizeTrackedUrl()` is the only live-post navigation/persistence boundary.
Only absolute HTTP(S) URLs survive. Invalid, relative, protocol-relative and
non-web schemes are inert. The publish dialog rejects them, renderers never put
them in `href`, and the normalized Supabase mirror drops them.

## Compatibility

Draft schema v7 is additive. v6 and older workspaces receive structural
defaults, keep their final verdict at experiment level, and load normally.
Projects with Outcome verdicts repair the materialized experiment summary from
the latest checkpoint without changing checkpoint history.

Production installs run:

`supabase/migrations/20260802_outcome_verdict.sql`

Then run the complete `supabase/audit.sql`; the outcome checkpoint contract must
PASS before production acceptance.

## Acceptance

- `javascript:`, `data:`, `mailto:`, relative and protocol-relative tracked
  URLs are not clickable or mirrored.
- 24h and 72h display their own Verdict.
- A legacy final Verdict is labelled once and never attached to a checkpoint.
- A second draft on the same channel receives a distinct Today task and can
  create a distinct Experiment.
- Local draft, Supabase meta, normalized mirror, Copilot context, Timeline and
  export agree on the history contract.
- Typecheck, offline tests, lint, format, build, desktop and 375px browser QA
  pass.
