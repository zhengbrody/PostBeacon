# C.1 provider acceptance and recovery corrections

2026-10-23, America/Los_Angeles. This is a bounded local provider-integration step,
not full authenticated production acceptance and not C.2 background Agent delivery.

## User-visible corrections

- Loading an unchanged local or Supabase-meta project now preserves the existing
  canonical, user-confirmed growth-goal fact and its verification timestamp. Previously
  hydration called `answerFact` again, changing the research context version without
  a user edit. Pending research could then become unconfirmable after refresh.
- A genuinely changed contract still replaces the old goal fact and blocks research
  prepared for that old goal. Inferred/malformed legacy goal facts are still repaired.
- Confirmed trial provenance retains its source's `truncated` warning through queue
  normalization/export/hydration. Previously `normalizeTrialSnapshot` dropped it.
  Already-lost historical warnings cannot be reconstructed and are not backfilled.

Both regressions were reproduced as failing tests before the fixes. Flat project and
Supabase-meta restoration are tested; these are JSON boundary tests, not a claim of
a fresh real Supabase account-isolation test. No new schema, env, vendor or storage
version is needed; the field already exists in the source receipt type.

## Explicit, small provider acceptance

The large golden eval is not used. `scripts/research-acceptance.ts` supplies one fixed
PostBeacon product description and an explicitly hypothetical acceptance scenario
on `example.org`. It is **not an observed customer quote or evidence of demand**.
Fetching is disabled. No private project, customer feedback, profile, email or account
token is read. Product facts are controlled test fixtures, not an Analyze result.

```bash
# Spends: one existing generateJsonOnce research invocation, OpenAI only by default.
npm run release:research

# Only after acknowledging the disclosed DeepSeek processing boundary:
RESEARCH_ACCEPTANCE_PROVIDERS=deepseek RESEARCH_ACCEPTANCE_DEEPSEEK_ACK=1 npm run release:research
```

`npm test` skips the live case. Calling `release:research` is the explicit live opt-in.
The selected batch is validated before credentials are loaded or any requests run:
no Claude, duplicate/unknown providers, missing selected keys or custom OpenAI endpoint.
DeepSeek is never a fallback and requires the additional acknowledgement. The existing
`generateJsonOnce` path retains one raw attempt, SDK retries disabled, a 20-second
model deadline and a 2,600 output-token cap. These are per-request limits, **not** an
atomic account/global spending budget. They do not complete C.2.

Actual provider provenance must match the selection. Outputs are normalized and pass
the existing deterministic trial/Truth Gate. `blocked` and `no-fit` remain honest
content outcomes, not reasons to retry until a favorable answer appears. Only a
review-ready controlled output exercises simulated dual confirmation, one ready
queue entry, duplicate rejection and local export/hydration. No publication or
customer activation is simulated into a real account.

The result distinguishes protocol, content and local continuity. Even a passing
result always has `productionAccepted: false`. Reports contain only bounded metadata,
enums, counts and local check booleans, never prompts, excerpts, drafts or upstream
errors. Future runs write `eval-results/research-acceptance-<provider>.json` (ignored
by Git) so a quiet test reporter cannot hide the detailed result.
