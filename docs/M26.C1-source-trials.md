# M26 C.1 — source-backed trial preparation

2026-10-12. Local implementation of a **vertical slice of roadmap C**, not the
complete Growth Agent. No commit, push or production deployment is claimed here.

## What changed and why

Today has a secondary **Find trial opportunities** workbench. The founder specifies
one audience, one real product task, a same-origin HTTP(S) trial entry, three steps,
one feedback question, a publication channel/venue and up to three public-source
excerpts. This turns marketing research into a concrete invitation to use a product,
without pretending the model has tested that product or verified a community’s rules.

`Submitted evidence → source receipt → tentative fit → trial kit review → explicit
confirmation → ready Today queue → review/edit → manual publish → existing Measure`

The source is **not** the publication venue. A GitHub discussion can motivate an
invitation on the founder’s own X account; source access does not imply permission
to reply or advertise in the source community.

Source cards distinguish user-provided excerpts, exact quote found, quote not found
and fetch failed. Publication dates, freshness, identity, demand and venue rules
remain unknown. A quote match proves only that the submitted extract contains the
quote, not that the proposed audience actually wants the product. Model fit is
always labelled a hypothesis, never an observed conclusion or confidence percentage.

## Safety and request budget

- `/api/opportunities` requires configured accounts and a verified signed-in caller;
  cross-origin requests fail before the auth/research seams. Body cap: 64 KB.
- Only the user-selected OpenAI or DeepSeek provider is eligible. Claude is not
  enabled for this path. One raw request, SDK retries disabled, 20s model timeout,
  2,600 output-token limit and 24,000-character serialized input bound. No model
  JSON-repair request or automatic provider fallback. Local trailing-comma parsing
  may still repair JSON syntax without another request. Other routes keep their
  existing failover behavior.
- Source fetching defaults off. Explicit per-source permission uses existing
  DNS-pinned SSRF-safe fetch, concurrency two, 8s per fetch, 2 MB body cap, no
  redirects and no paid renderer. Submit a canonical URL if a source redirects.
  Known social hosts are excluded from generic fetching; this is not a comprehensive
  permission/robots/legal audit of every possible host. Only authorized public
  excerpts/pages should be submitted.
- Fetched bodies are transient and never persisted or sent to the model. Only
  submitted short excerpts and confirmed/observed product facts enter the model.
  Launch goals/stage/assets are not product-capability evidence. The model cannot
  invent source IDs, source URLs, quotes, permission or fact IDs.
- Obvious emails in excerpts are removed. This is **not** comprehensive automatic
  anonymization: the founder must remove handles, names and confidential content.
- Current deterministic Truth Gate, exact approved entry-link checks and literal
  banned-claim checks block kit confirmation/copy. These are bounded checks, not
  a claim of complete semantic correctness. Founder review remains necessary.
- Changes to product/facts/goal/banned claims invalidate unconfirmed research.
  Changing the form also requires a fresh request; old results cannot be confirmed
  as though the new steps had been researched. Late cross-project/account responses
  are discarded by both the hook and reducer.
- Both acknowledgements are required: the founder tested the entry/steps/claims,
  and manually checked the actual publication rules. Their report is not upgraded
  into independent server verification.
- The queued draft can still be edited, but publication re-runs the same approved
  entry/literal banned-claim gate plus the current Truth Gate in the dialog and reducer.
  Changed links cannot silently acquire the original trial provenance.

The inherited daily guard is not an atomic global dollar-budget system: metering
may be disabled and Pro is unmetered. This slice bounds individual requests, not
arbitrary parallel/account-wide spend. C.2 must add durable reservations before
claiming a resumable/budgeted autonomous Agent.

## Architecture and persistence

`opportunityResearch.ts` owns isomorphic normalization, eligibility, context version
and trial gates. `opportunityResearchServer.ts` owns bounded fetch/model orchestration.
`OpportunityWorkbench` owns only ephemeral form/review state. Project changes go
through `launchFlowReducer`, not independent component state.

Finished receipts live in `workspace.opportunityResearch`. They are **not** AgentRun
jobs: no durable queued/running state, lease, retry or resume is inferred from JSON.
Explicit confirmation atomically appends one ready draft and independently identified
planned experiment. Confirmation is idempotent and respects the existing 40-entry /
12-drafts-per-channel limits. Confirmed trials are exploratory, not controlled A/B tests.

Each confirmed plan freezes source/quote/verification, proposed trial audience,
task, entry, three steps, feedback question and the founder’s rule-check timestamp.
Publish carries that provenance plus the existing facts/voice/draft/success snapshot
to its execution. Discarding research cannot erase confirmed or historical trials.
The publication dialog locks the queued draft and approved venue to prevent recording
an unrelated post against that plan. Publishing is a self-report, not proof of use.

Schema v11 uses existing owner-scoped `projects.meta.workspace` JSON. No SQL migration,
environment variable, vendor, connector or billing change is required. The normalized
workspace mirrors are still best effort; do not reconstruct full trial provenance
from them. JSON/Markdown export and existing parent-project deletion/retention cover
these fields. Privacy inventory/public notice describes the submitted excerpts and
trial instructions. Research is excluded from unrelated Copilot context.
