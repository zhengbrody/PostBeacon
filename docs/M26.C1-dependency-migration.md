# C.1 approved dependency security migration

2026-10-24, America/Los_Angeles. The user explicitly approved execution after the
reason for the major-version change was explained. This is a local security and
compatibility change, not C.2 Agent delivery, model migration or production promotion.

## Scope

- Zod 3.25.76 → 4.6.7, and the OpenAI SDK 4.104.0 → 7.43.0. The installed SDK
  declares Zod 4 compatibility; no separate nested vulnerable Zod copy remains.
- Preserve `lib/llm.ts` as the only model transport. No production transport code
  change was required: Chat Completions, JSON mode, token budgets, configured model
  overrides, DeepSeek base URL and actual-provider provenance remain unchanged.
- Defaults remain `gpt-4o` and `deepseek-chat`; Claude is not re-enabled. Research
  remains one selected-provider request with no SDK retry, JSON repair or fallback;
  ordinary generation retains its existing disclosed fallback behavior.
- Zod's `invalid_value` replaces the old enum issue code. Public validation errors
  remain static and do not echo rejected enum/literal values. Use the current
  `z.ZodType` generic rather than the deprecated compatibility alias.
- Preprocess non-finite historical metrics before Zod's stricter number validation.
  Null, NaN, infinities and negative invalid observations remain absent, not zero;
  ordinary numeric observations remain intact. This does not introduce coercion of
  strings or a new metric-writing permission for the model.
- CI gains `audit:dependencies` (high/critical blocking, no force-upgrade). README
  states Node 22+; the existing CI runtime is Node 22. No production runtime setting,
  SQL, environment variable, vendor, price, user data or model was changed.

## Regression evidence

Before the adapters were fixed, new tests reproduced five failures: enum/literal
public error compatibility and three non-finite legacy metric cases. They pass
after the change. Additional bounded-collection coverage checks that an oversized
platform list yields one size failure rather than per-element failure accumulation.

`tests/llmSdkCompatibility.test.ts` imports the actual installed SDK, replacing only
the fetch transport and all relevant API keys/model environment values with offline
fixtures. Its nine cases check both provider URLs, exact request body/model/token/JSON
fields and bearer selection, no research retry/fallback/repair on HTTP or transport
failure, and ordinary-generation fallback and non-retryable rejection semantics.
No request reaches a provider. The existing SDK-option test still checks the
research 20-second timeout and zero-retry configuration.

These checks do not establish current live provider availability, quality of a new
model output, real Supabase isolation, cloud save/deletion or desktop/mobile visual
acceptance. Prior provider acceptance predates this SDK migration and is not
relabeled as a fresh paid test.

## Sources and release boundary

The [official OpenAI SDK documentation](https://developers.openai.com/api/docs/libraries)
was consulted before migration; installed SDK types/package metadata established
the selected version's Node/Zod requirements. The existing API family was preserved
rather than adopting a new model or Responses API during a security fix.

The prior audit and its historical two-high-advisory result remain documented in
[the cloud-boundary audit](M26.C1-cloud-boundary-audit.md). A zero-result dependency
scan reflects known advisories at scan time, not a zero-vulnerability guarantee.
No deploy or C.2 background job is authorized by this migration alone.

## Final local verification

- Clean lockfile install (`npm ci`) under Node 22.23.4 passed. Full dependency and
  production-only `npm audit` each reported zero known vulnerabilities on October 24.
- 568 offline tests passed; three gated live tests skipped (53 passing test files,
  two skipped). This adds 18 regression cases to the 550-test audit candidate.
- Typecheck, ESLint, formatting, production build (Next 15.5.28 / Node 22.23.4), and
  `git diff --check` passed. CI configuration was updated but no remote CI run is
  claimed: changes remain local and uncommitted.
- Built-app signed-out HTTP smoke passed all six probes at `http://localhost:3100`,
  checked at `2026-10-24T07:27:08.113Z`. Pages returned 200, unsigned research/export
  401, foreign research origin 403, and metrics 503 (closed, not configured-report
  acceptance). The local audit server was stopped after the checks.
- The build reports `/app` at 126 kB and 293 kB first-load JS, compared with the
  preceding audit candidate's 114 kB / 281 kB. This is an observed build-size tradeoff,
  not a measured runtime speed result; no unrelated client-schema refactor was added.
- Node 22 server preload emitted a non-fatal SQLite experimental warning. A traced
  startup located the external require in Next's preload; the installed Undici runtime
  feature detector imports `node:sqlite`. Importing the OpenAI SDK alone did not emit
  it. No SQLite store or cache is configured by the app, and no warning suppression or
  unrelated dependency rewrite was added. This run is not described as warning-free.

The local dependency gate is now closed, not the entire release gate. Production
has not received these changes; no fresh live-provider request, real QA account
save/refresh/export/isolation, database ownership constraint, cross-device revision
control or visual browser check was performed. Those acceptance boundaries, followed
by C.2 durable jobs/atomic budgets, remain separate work.
