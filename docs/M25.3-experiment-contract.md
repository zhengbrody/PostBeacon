# M25.3 — Auditable Prepare and Publish

## Problem

M25.2 reduced Strategy to one channel decision, but Prepare still behaved like a draft
viewer. The user could not answer four basic questions from one surface:

1. Who and where is this experiment for?
2. What single variable is changing?
3. What observed result counts as success?
4. Which facts, platform rules and inferences shaped the draft?

The Truth Gate could block unsafe copy, but its recovery path was also easy to miss. A
founder had to discover Copilot separately and trust a rewrite without a useful before/after
view.

## Product contract

### Experiment Contract

Prepare projects one contract from canonical state; it does not introduce a second mutable
contract object:

- audience comes from `ProductProfile`;
- venue and angle come from the selected `PlatformRecommendation`;
- the tested variable is the selected Hook;
- the target and 24h/72h window come from `SuccessContract`.

Publish shows the same projection and explains that the existing Experiment fields — venue,
angle, selected hook and snapshotted Success Contract — preserve the run. Later workspace
changes cannot rewrite it.

### Change receipt

Selecting another Hook visibly records:

`Variable changed · Hook: previous → candidate`

The receipt is interaction state, not a fabricated confidence score. The selected hook itself
continues through the existing reducer-backed post update and is saved as `Experiment.variant`
when published.

### Why this draft

The disclosure is conservative:

- evidence includes only Fact IDs explicitly cited by the scored recommendation;
- the platform rule comes from the deterministic platform catalog;
- the selected angle is labelled separately;
- inferred venue, angle or facts are called out as inferences.

It never claims a paraphrased sentence is a direct citation.

### Truth Gate repair

A blocked draft now offers `Repair issues with Copilot`. The request names the deterministic
issue codes and asks for one complete `generate_variant` proposal. Existing Copilot controls
remain authoritative:

- the proposal shows Hook and Body before/after;
- Apply adds a variant and preserves the original;
- Dismiss leaves state untouched;
- the deterministic Truth Gate reruns on the applied post before copy or publish.

No model response can bypass the proposal/confirm boundary.

### Share Kit

Prepare includes a lightweight, deterministic sharing kit:

- three screenshot jobs in narrative order: Decision → Draft proof → Learning loop;
- a focus note and alt text for each image;
- an explicit privacy-redaction reminder;
- a bounded three-part X draft and a LinkedIn version.

The kit does not invent outcome metrics, post automatically or capture screenshots itself.

## Compatibility and data changes

- No SQL migration.
- No environment variable or vendor change.
- No storage version change: canonical persisted fields already hold the publish contract.
- Legacy recommendations without Fact IDs or a Success Contract receive explicit missing-data
  labels instead of reconstructed evidence.

## Acceptance

- Prepare displays audience, venue, Hook, angle and success rule.
- Switching Hook immediately shows the previous and selected value.
- Why this draft separates cited evidence, catalog rule and inference.
- A blocked Truth Gate exposes a review-first repair path.
- Copilot variant proposals show Hook and Body before/after.
- Share Kit contains three ordered screenshots, alt text, privacy guidance and bounded copy.
- Publish repeats the contract and states which values are snapshotted.
- Desktop and 375×812 viewport have no horizontal overflow or browser warnings/errors.
