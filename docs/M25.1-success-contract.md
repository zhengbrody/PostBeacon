# M25.1 — Compact Diagnose and Success Contract

## Product problem

Diagnose exposed good evidence, but it still read like a report. More importantly,
`conversionGoal` was only a string: the workspace displayed it while Verdict used
global thresholds such as any signup or 200 impressions. The user had not actually
defined what a meaningful result meant.

## Compact Diagnose

The first screen now contains only:

- product;
- audience;
- main value;
- primary goal;
- deterministic counts of verified, inferred and unknown facts.

Clarifying questions remain visible because they can change sequencing. Source
coverage, exact quotes and the full Fact Ledger live under one `Review all evidence`
disclosure. The working diagnosis and full profile editor are also disclosures.
Nothing was deleted; hierarchy changed.

## Success Contract

`WorkspaceState.successContract` is the single current contract:

```ts
{
  primaryGoal: string;
  primarySignal: "impressions" | "replies" | "clicks" | "signups" | "revenue";
  baseline?: number;
  minimumResult: number;
  evaluationWindow: "24h" | "72h";
}
```

Goal selection creates a visible, editable default. It never creates an outcome or
pretends a baseline exists. API validation and the persisted-data normalizer reject
unknown signals, non-finite values, negative baselines and zero/negative targets.

## Historical correctness

The reducer copies the current contract onto an Experiment atomically when manual
publish is confirmed. Later workspace edits affect only future experiments. Old
experiments without a contract continue through the legacy Verdict path; PostBeacon
does not reconstruct a historical target that was never stored.

## One contract, all consumers

- Strategy and draft generation receive the bounded contract as data.
- Copilot sees the same contract and may not substitute another metric.
- Publish confirmation shows the rule that will be frozen.
- Measure puts the primary signal first and folds secondary observations.
- Verdict reads only the snapshotted primary signal for target decisions.
- Markdown/JSON exports include the workspace contract and each experiment snapshot.

Contract-aware Verdict behavior:

- target reached → `supported`;
- baseline improved but target not reached → `promising`;
- early progress before the final window → `promising` or `no-signal`;
- primary signal absent → `no-signal` / insufficient evidence;
- measured target miss at the final window → `weak`.

The existing call vocabulary is retained for compatibility. A later calibrated
Verdict milestone may introduce explicit `target reached`, `insufficient evidence`,
`target missed` and invalid/confounded states without losing these stored inputs.

## Persistence and infrastructure

Draft schema v9 stores the contract inside the existing workspace JSON in localStorage
and `projects.meta`. Normalized workspace tables remain a best-effort mirror; project
meta is still the hydration source. No SQL migration, environment variable, analytics
event or external service is required.

## Acceptance

- Diagnose opens as a compact decision summary.
- Full evidence remains reviewable and editable.
- A strategy cannot be built without a valid Success Contract.
- Publish freezes the exact contract onto the experiment.
- Changing the workspace goal cannot rewrite a published experiment.
- Measure leads with the configured primary signal.
- Missing primary-signal data is never interpreted from secondary metrics.
- v1–v8 projects load; old experiments preserve legacy Verdict behavior.
