# M25.2 — Focused Strategy Decision

## Product problem

Analyze and Diagnose now establish a trustworthy product profile and an explicit Success
Contract, but Strategy still opened as a long report with four channels preselected. The
founder received nineteen ratings and another batch-generation decision at the moment they
needed one executable next move.

M25.2 changes the Strategy step from a report-first channel picker into a decision:

1. show one recommended experiment;
2. make its venue, rationale, effort, risk and observable signal inspectable;
3. explain why the computed #1 outranks #2;
4. prepare content for that one channel only;
5. keep alternatives and the complete nineteen-channel analysis available on demand.

## State and ranking contract

`FlowState.selected` remains an array for saved-project and generated multi-channel plan
compatibility, but an unfinished Strategy is now normalized to exactly one platform ID.

- Score is the first ordering key.
- The canonical platform catalog order breaks equal scores.
- Platform ID breaks the impossible remaining tie.
- A legacy unfinished project with several selections keeps its highest-ranked selected
  channel.
- A historical project that already has generated content is not rewritten or collapsed.
- Selecting an alternative replaces the current Strategy choice; it cannot leave the
  Strategy with zero or multiple choices.

The ranking logic lives in `lib/strategyDecision.ts`; neither the component nor the model
owns an independent sorting rule.

## Decision surface

The first card shows:

- recommended channel and exact venue when one is available;
- grounded/inferred venue provenance;
- concrete best move;
- `Why now` from the recommendation rationale;
- fit to the current primary goal;
- an explicitly labelled planning estimate derived from catalog effort;
- the stored risk reason, or an honest legacy-plan absence;
- the Success Contract signal and target;
- a deterministic comparison with #2.

The only primary action is `Prepare this experiment`. It calls the existing generation API
with one platform ID and never posts automatically.

Secondary disclosures contain:

- the top three alternatives;
- all ranked channels and score breakdowns;
- positioning, audience, phases and niche discoveries.

## Trust boundaries

- No new model call or prompt was introduced.
- The fictional walkthrough projects an already-baked selected channel locally; Strategy
  can never trigger a provider call while the UI promises example data/no model call.
- No score, confidence or causal explanation is invented in the browser.
- Unverified venues remain visibly unverified.
- Planning time is labelled as an estimate, not measured user data.
- The existing Success Contract remains the only source for the observable signal.
- Existing safe-link and discovery provenance rules are unchanged.
- No SQL, environment variable, vendor, storage version or analytics payload change is
  required.

## Acceptance criteria

- A new Strategy selects exactly the deterministic #1 channel.
- Equal scores resolve consistently without trusting model array order.
- The first screen presents one decision and one primary CTA.
- `Compare alternatives` shows the top three and supports an explicit replacement choice.
- `Explore all channels` preserves every recommendation and its score breakdown.
- Initial generation receives exactly one platform ID.
- Existing generated multi-channel projects load unchanged.
- Legacy unfinished multi-selection projects migrate to one focused choice.
- Empty/fallback/legacy explanation states are honest and do not fabricate missing data.
- Desktop and 375 px mobile have no horizontal overflow, console errors or blocked controls.
- Typecheck, offline tests, lint, format and production build are green.
