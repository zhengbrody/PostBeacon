# C.1 pre-cloud acceptance: async ownership, ordered saves and complete exports

2026-10-23, America/Los_Angeles. Scope: targeted architecture/code audit plus
local regression fixes before real-account acceptance. **Not a zero-bug certification,
production RLS acceptance or delivery of C.2.**

## Findings and corrections

| Finding | Evidence / impact | Local correction |
| --- | --- | --- |
| Late model results could repopulate a different account/project | `resetAccountBoundary` cleared state but did not invalidate all Analyze/Strategy/Generate/rewrite awaits. C.1 alone had an explicit context check. | Shared `asyncScope` tickets, abort signals through `lib/api`, post-await checks, and synchronous identity invalidation in the flow Hook. Old errors/finalizers cannot take ownership of a newer operation. |
| Concurrent saves could finish out of order | `useAutosave.persist` allowed simultaneous upserts and unawaited mirror writes. A stable project ID prevented duplicate rows, not stale-overwrites. | Serial writes keyed by owner/project; canonical save and mirrors stay ordered. Other projects do not wait behind an unrelated slow write. Old identities cannot clear browser storage, mark a new project saved, or start further mirror stages. |
| Account commands could drift to the current session | Export waited for save and then independently resolved the bearer. Project-list requests and command callbacks had no stale-owner guard. | Bind export/delete to the initiating user before sending; suppress stale downloads/messages/redirects; explicitly owner-filter project queries/deletes; remount account tools on identity change. Existing irreversible server requests cannot be undone by a client abort. |
| Large account exports silently stopped at the server row cap | A failing regression reproduced 2,501 project rows exported as only 1,000. | Owner-filtered, stable ordered pagination with exact counts. Advance by actual returned length so lower server caps do not skip rows. Missing/changing counts, later failures, unexpected empty pages and safety limits stop export instead of returning partial success. |
| Historical dependency-risk note was obsolete | Fresh runtime audit initially reported 1 critical and 7 high package entries. | Compatible Next 15.5.28 / matching ESLint config, patched transitive packages, and a same-major PostCSS override to the patched root version. No framework major upgrade, model change or force-install. |

Plan data still belongs to `launchFlowReducer`, HTTP calls to `lib/api`, and
canonical saved state to owner-scoped `projects.meta`. `asyncScope` is a small
ephemeral request/write coordinator, **not** another plan store or an Agent job
system. Workspace mirrors remain best effort and are not safe as C.2's job ledger.

## Regression evidence

- Actual React Hook tests use React's renderer/effects in jsdom (development-only
  dependency). They cover account-switch while auth is pending, old write completion,
  ordered old/new saves, unresolved auth, old model success after reset/project load,
  and an old failure while a newer model call is loading.
- Pure async tests cover invalidation, latest-request ownership, context edits,
  ordered writes, failure recovery, stale queued work, and independent owner/project
  queues. Client API mocks prove no fetch occurs if auth resolves to the wrong owner
  or the request was aborted before transmission.
- Export tests cover the 1,000-row cap reproduction, lower server caps, exact owner
  filters, missing/changing counts, incomplete pages, later table/query errors and
  the bounded page limit. Missing legacy tables still return empty only on their
  initial read.
- These tests use mocked network/storage boundaries. They do **not** establish
  real Supabase isolation, live account deletion, or a transactional export snapshot.

## Remaining boundaries / next step

1. Complete and verify the now-approved major dependency migration before release;
   see the separate migration report for the current local gate result.
2. Run the dedicated real QA account save/refresh/export and approved second-account
   isolation workflow. Do not create users, harvest tokens, delete accounts or alter
   production SQL as a shortcut. No real model calls are needed for these local regressions.
3. Current save ordering is per Hook instance and owner/project. Concurrent browser
   tabs/devices still have last-writer-wins semantics; server revision/CAS is not implemented.
4. Existing normalized child tables have owner RLS but ID-only parent foreign keys.
   Parent/child ownership consistency needs a dedicated DB check and validated composite
   ownership constraints before those relations hold authoritative Agent jobs. This
   code audit did not test a production exploit or claim that arbitrary users can read
   each other's project content. No FK/schema migration was applied here.
5. Only after these gates, start C.2 durable runs/steps, atomic spending reservations,
   cancellation/resume and export/delete/retention coverage. No new Agent execution
   feature was implemented during this audit.
